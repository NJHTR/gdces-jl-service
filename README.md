# 监理 AI 服务

## 四份文档（先看这个）

项目跨了很多轮开发，**不靠记忆，靠文档**：

| 文档 | 回答什么 | 什么时候改 |
|---|---|---|
| `docs/GOAL.md` | 为什么做、做到什么算成功、不做什么 | 极少改。改它等于改产品方向 |
| `docs/PLAN.md` | 要做什么、做到哪一步 | 每完成一项就改 `[ ]` → `[x]` |
| `docs/STATUS.md` | **现在**做到哪、跑着什么、有什么坑 | 每次开工和收工各更新一次 |
| `docs/DECISIONS.md` | 当时为什么这么选、代价是什么 | 做了重要选择就追加一条 |

### 开工第一件事

```bash
bash scripts/progress.sh
```

一条命令打印：服务状态、数据量、代码状态、计划里没打勾的、已知问题、下一步。

### 收工最后一件事

更新 `docs/STATUS.md`（只写事实，附实测输出），然后提交：

```bash
git add docs/STATUS.md
git commit -m "docs(状态): 今日进展 —— xxx 已完成，yyy 待续"
```

### 提交格式

```
类型(模块): 中文说明

- 一条提交只干一件事，不要混
- 类型：feat / fix / refactor / docs / chore / style
- 模块：bff / 工具 / 服务端 / 现场 / 契约 / 部署 / 运维 / 状态
```
