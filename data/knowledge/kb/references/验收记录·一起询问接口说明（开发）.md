# 验收记录 ·「一起询问」模式 接口说明（开发）

> 适用对象：监理通后端 / LLM 编排 / 小程序前端
> 配套数据：`验收要点库（结构化索引）.json`（机器读）、`验收要点库（询问模式）.md`（人/RAG 读）
> 配套模版：`验收记录.docx`（④ 验收内容 = 一起询问；⑤ 验收结论 = 据全部回复整理）

## 1. 设计目标（与模版一致）

验收内容**不做逐项勾选**，而是：

1. 系统按用户「文字 / 图片水印」识别确认 **验收类型、分部工程、关键工序/关键部位**；
2. 据此从要点库一次性（**一起**）带出该工序**全部**监理验收要点并转询问式；
3. 用户在**一个整体回复**中就把所有要点答复（可逐条、也可整体描述）；
4. 系统**根据用户全部回复**逐条归集每个要点的结论（符合 / 不符合 / 不适用 + 说明）；
5. 汇总生成「验收结论」。

要点：问是**一起问**，答是**一次答**，整理是**按全部回复逐项归集**。

---

## 2. 数据源：结构化索引 JSON

文件：`验收要点库（结构化索引）.json`

### 顶层结构
```json
{
  "meta": {
    "说明": "...",
    "询问式规则": "陈述式要点无损转写为「请确认：<原句> □符合 □不符合 □不适用（说明：____）」",
    "总条目数": 320,
    "附件1条目": 181,
    "附件2条目": 139
  },
  "entries": [ /* 320 条，见下 */ ],
  "by_division": { "地基与基础·地基处理": [1,2,...], "XXX单位工程 / XXX分部": [..], ... }
}
```

### 单条 entry 字段
```json
{
  "序号": 1,
  "来源": "附件1-房屋建筑工程",
  "单位工程": "",                       // 附件2 才有，附件1 为空
  "分部工程": "地基与基础·地基处理",      // 附件1 主键
  "关键工序_关键部位": "地基基底验收",
  "验收要点_原文": ["① 核查基底土质…", "② 清除浮土…", "③ 钎探记录…", "④ 会同…"],
  "验收要点_询问式": [
    "请确认：① 核查基底土质、标高、平面位置与勘察报告及设计要求一致　□符合　□不符合　□不适用（说明：____）",
    "请确认：② 清除浮土、积水、杂物　□符合　□不符合　□不适用（说明：____）",
    "请确认：③ 钎探记录齐全，异常部位已处理并经设计确认　□符合　□不符合　□不适用（说明：____）",
    "请确认：④ 会同勘察、设计、建设单位共同验槽并签认　□符合　□不符合　□不适用（说明：____）"
  ],
  "建议验收类型": "质量验收"
}
```

### by_division 索引
- 附件1：key = `分部工程`（如 `地基与基础·地基处理`），value = 序号列表。
- 附件2：key = `单位工程 / 分部工程`，value = 序号列表。
- 续行（分部工程为空）已在生成时继承上一非空值，无空键。

## 3. 运行时流程（6 步）

```
① 信息确认  ── 输入：用户文字 / 图片水印 OCR 文本
             输出：{ 验收类型, 分部工程, 关键工序_关键部位 }
             （验收类型 ∈ {材料进场验收, 隐蔽验收, 质量验收, 危大验收}，
               取值以本步识别确认为准，不取 index 的「建议验收类型」）

② 带出要点  ── 输入：分部工程 + 关键工序_关键部位
             查 by_division → 序号列表 → 取 entries 中对应条目
             输出：该工序的全部 验收要点_询问式（数组）

③ 一起询问  ── 把全部 验收要点_询问式 拼成一段询问块（见 §4）
             前端一次性展示 + 一个多行「用户回复」输入框

④ 用户回复  ── 用户就所有要点一并作答（单条文本，可逐条/整体）
             前端收集为 user_reply: string

⑤ 系统整理  ── 调用 LLM 归集（见 §5）：items + user_reply → 逐条结论
             输出：aggregated[] = { item_index, conclusion, note }

⑥ 验收结论  ── 据 aggregated 生成（见 §6），写入模版 ⑤
```

---

## 4. 询问块拼装规则（一起带出）

取 `验收要点_询问式` 数组，**不做逐项 UI 勾选框**，直接顺序拼接为一段文本块：

```
【验收内容】（系统按「<分部工程> · <关键工序_关键部位>」自动带出，共 N 项，请一并答复）

请确认：① <要点1原文> □符合 □不符合 □不适用（说明：____）
请确认：② <要点2原文> □符合 □不符合 □不适用（说明：____）
...
请确认：⑩ <要点10原文> □符合 □不符合 □不适用（说明：____）

请就上述全部要点一并回复（可逐条逐项，也可整体描述；不符合/不适用须写明原因）：
```

说明：
- 询问块里的 `□符合/□不符合/□不适用` 仅作**语义提示**，因为「一起询问」模式下用户是**整体回复**而非逐项勾选，UI 不必渲染复选框。
- LLM 可在拼装时把「请确认：<原句>」润色成更自然的中文问句（不改变原权威措辞核心），但默认用原句即可。

---

## 5. 用户回复归集（核心：按全部回复逐条归集）

输入：
- `items`：本工序的 验收要点_询问式 数组（带序号标记 ① ② ③…）
- `user_reply`：用户整体回复文本

输出（`aggregated`，强结构）：
```json
[
  {"item_index": 1, "conclusion": "符合",     "note": ""},
  {"item_index": 2, "conclusion": "符合",     "note": ""},
  {"item_index": 3, "conclusion": "不符合",   "note": "③点钎探记录缺失，已要求补做"},
  {"item_index": 4, "conclusion": "不适用",   "note": "本工程无此工序"}
]
```
`conclusion` 枚举：`符合 | 不符合 | 不适用`。

### 推荐 LLM 调用约定（伪代码）
```python
def aggregate_reply(items: list[str], user_reply: str) -> list[dict]:
    prompt = f"""你是监理验收助手。下面是一并带出的若干验收询问项（已标序号 ① ② ③…），
以及监理人员就全部要点给出的整体回复。请逐条判定每条要点的结论。

【询问项】
{chr(10).join(items)}

【监理人员整体回复】
{user_reply}

请严格返回 JSON 数组，每个元素：
{{"item_index": <序号整数>, "conclusion": "符合|不符合|不适用", "note": "<原因/说明，无则空字符串>"}}。
必须覆盖全部询问项，不要遗漏；结论只能在三个枚举内。"""
    # 调用 LLM，要求 JSON 输出，解析并校验长度 == len(items)
    return parse_json(llm(prompt))
```

校验：返回数组长度须 == `items` 长度；任一 `conclusion` 不在枚举内 → 重试或回退到「待人工确认」。

## 6. 验收结论生成

输入：`aggregated[]`
输出：结论文本（写入模版 ⑤）

规则（与模版示例一致）：
- 全部为「符合」→ `验收合格，同意进入下道工序。`
- 存在任一「不符合」→ `验收不合格，签发整改通知并限期复验。`（可附带具体不符合项摘要）
- 仅「不适用」且无「不符合」→ 视为合格相关项通过，结论为 `验收合格（N 项不适用，已确认）。`

可选：把 `aggregated` 的逐条归集先以「系统整理」形式展示给用户核对（模版示例里的「→ 系统整理」行），确认无误再落结论。

## 7. 字段映射回模版（docx 表单）

| 模版字段 | 取值来源 |
|---|---|
| ① 验收类型 | §3 第①步识别确认结果 |
| ② 分部工程 | §3 第①步识别确认结果 |
| ③ 关键工序、关键部位 | §3 第①步识别确认结果 |
| ④ 验收内容 | §4 拼装的询问块 + 用户回复（运行承载区） |
| ⑤ 验收结论 | §6 生成 |
| ⑥ 验收日期 / ⑦ 照片 / ⑧ 单位人员 / ⑨⑩ 签名 | 用户手填或系统采集 |

## 8. 端到端示例（地基基底验收）

- 信息确认：验收类型=隐蔽验收；分部工程=地基与基础·地基处理；关键工序=地基基底验收
- 带出要点（序号 1，共 4 项询问式）
- 一起询问块：
  ```
  请确认：① 核查基底土质、标高、平面位置与勘察报告及设计要求一致 … □符合 □不符合 □不适用
  请确认：② 清除浮土、积水、杂物 … □符合 □不符合 □不适用
  请确认：③ 钎探记录齐全，异常部位已处理并经设计确认 … □符合 □不符合 □不适用
  请确认：④ 会同勘察、设计、建设单位共同验槽并签认 … □符合 □不符合 □不适用
  ```
- 用户回复（整体）：「基底土质标高位置都对得上勘察报告，浮土积水都清了，钎探记录齐全没异常，各方也一起验槽签了字。」
- 系统整理：`[{1:符合},{2:符合},{3:符合},{4:符合}]`
- 验收结论：`验收合格，同意进入下道工序。`

## 9. 备注 / 待确认

1. 验收类型**不**从 index 的「建议验收类型」取，必须从用户文字/图片水印识别确认（index 仅作兜底提示与 RAG 检索辅助）。
2. 「一起询问」不渲染逐项复选框；若后续想保留勾选 UI，可在 §4 询问块基础上加逐项卡片，但**回复仍是一次性整体提交**。
3. 当前 index 共 320 条（附件1 181 + 附件2 139），已剔除两个「合计」汇总行；若源表更新需重跑 `tmp/build_ys_index.py` 重新生成。
