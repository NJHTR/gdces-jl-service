# 引用与出处

## 为什么要做

监理的每个结论都要能回到出处：谁说的、哪条、哪张图、哪一行。
所以**你读过什么，就要标什么**，并且在正文里用 [1] [2] 指出来。

## 怎么写（只做这一件事）

正文里，在你用得上的那句话后面写 `[1]`、`[2]`（顺序 = 末尾引用块的顺序）。

回复**最后**附一个块（正文之外，单独起行）：

```
<oai-mem-citation>
<citation_entries>
knowledge/checkpoints/主体结构-·-混凝土结构.md:88-90|note=[钢筋隐蔽验收要点]
records/photos.md:12-12|note=[10:30 现场照片：连墙件缺失]
standard://JGJ 130-2011#6.4.3:1-1|note=[偏离主节点≤300mm]
thread://<会话号>/message/512:1-1|note=[用户原话：外架连墙件缺失]
web://m.nmc.cn/weather:1-1|note=[深圳天气：晴转多云]
</citation_entries>
<rollout_ids>
</rollout_ids>
</oai-mem-citation>
```

## 格式硬要求（写错就解析不出来）

```
必须是 路径:起始行-结束行|note=[一句话]
行号必须是数字，且起始 ≤ 结束
没行号的东西（规范条号/会话/网页）用伪路径 + :1-1 占位
```

| 你读到的是 | 写成 |
|---|---|
知识文件 | `knowledge/.../xxx.md:88-90` |
照片索引 | `records/photos.md:12-12` |
记忆 | `homes/<uid>/memories/MEMORY.md:12-14` |
规范条号 | `standard://JGJ 130-2011#6.4.3:1-1` |
用户原话 | `thread://<会话号>/message/<消息号>:1-1` |
网页 | `web://<域名><路径>:1-1` |

## 规矩

1. **只标真读过的**。没读就别写；编出来的出处比没有更糟。
2. 一张图一条；一句话一条；不要合并成一条。
3. `note` 写「你从这段里得到了什么」，一句话，别抄原文。
4. 最多 8 条；多了说明你在堆砌，挑真正支撑结论的。
5. 网页来源：只写你确实看到过的域名；没核实就别标。
