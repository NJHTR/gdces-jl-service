## 本机工具

```
jl-tool list                        # 看有哪些工具（永远以这个为准）
jl-tool <工具名> '{"键":"值"}'        # 调用，参数必须是 JSON
```

当前提供的能力（清单以 `jl-tool list` 为准，这里只是说明它们干什么）：

- `get_project` 读工程项目信息（名称、编号、地址、21 个概况字段）
- `search_records` 检索该项目的文书与现场记录
- `search_standards` 用自然语言检索规范条文（如「连墙件 间距」）
- `create_doc_draft` 在工作区生成文书草稿并 git 提交
- `validate_doc` 出稿前按 schema 自查字段齐不齐
- `get_context` 一次拿到项目信息 + 项目记忆 + 工作区路径

## 出稿的规矩

1. 用户说「出/写/生成 通知单、记录、日志」时，**必须真的调用 `create_doc_draft`**，
   不能只在回复里描述文书内容。
2. 写文书前先用 `search_standards` 查到依据，把条号写进 `bases`。
3. 出稿前先调 `validate_doc` 自查：缺什么它会告诉你；缺的就留空，**别编**，交给人补。
4. `create_doc_draft` 会把文件写进项目工作区并 git 提交。

## 为什么这么做

这些是**流程契约**，不是模型能力。写进工具里比写进提示词可靠：
工具会真的挡你（validate_doc 报错就是报错），提示词只是"希望它记得"。
