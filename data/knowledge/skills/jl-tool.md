## 怎么用工具（当前真实情况）

工具通过命令行调用，**命令已经在 PATH 里，直接用**：

```
jl-tool <工具名> '<JSON 参数>'
jl-tool list              # 只看清单时用
```

**不要去找它的实现**：没有 python 模块，也不要 `find`，也不要读 `scripts/jl-tool`。
它就是这条路 —— 你自己去找一次，会多花 8 次工具调用、二十几秒。

例：

```
jl-tool search_standards '{"query":"连墙件 间距"}'
jl-tool create_doc_draft '{"projectId":"yun-gu-3qi","kind":"监理通知单","obj":"4#楼东侧外架","fields":{"部位":"4#楼东侧外架"}}'
```

## 出稿的规矩

1. 用户说「出/写/生成 通知单、记录、日志」时，**必须真的调 `create_doc_draft`**，
   不能只在回复里描述文书内容，也不要用 shell 手写 md（手写的不会入库，用户看不到）。
2. 写文书前用 `search_standards` 查依据，把条号写进 `bases`。
3. 出稿前用 `validate_doc` 自查：缺什么它会告诉你；缺的就留空，**别编**。
4. **缺字段不要追问** —— 留空交给人补，监理员在工地上没空回答五连问。
5. `create_doc_draft` 会写文件、提交、入库，一步到位。

## 找历史材料

- `search_records` 查这个项目的文书
- `search_photos` 按描述查现场影像（照片和语音都在这）
- `get_context` 一次拿到项目信息 + 记忆 + 工作区路径
