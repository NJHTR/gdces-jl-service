# 越用越聪明（长期）· 认知架构

> 目标：不是"这几轮对话更聪明"，而是**几年尺度上**越来越准、越来越省事。
> 约束：不加提示词、不做硬编码判断、不重复造轮子。

---

## 一、判断：聪明来自三件事，不来自提示词

```
证据（读过什么、出处在哪）
反馈（哪个结论被判对/判错）
检索（下次能不能把这些找回来）
```

提示词只是"怎么说"。**说得多不会让它更准，只会更容易冲突** —— 这是我们反复验证的。

所以架构上只做三件事：**把证据留下来、把反馈接上、把检索做对。**

---

## 二、三层结构（全部用引擎原生能力，不自研）

| 层 | 存什么 | 存在哪 | 生命周期 | 谁写 |
|---|---|---|---|---|
**事实层** | 读过的原文、条文、照片描述、项目规矩 | 文件 + git（`kb/`、`records/`、`standards/`） | 几年 | 人 + 项目 agent |
**程序层** | 怎么做事（出稿、复核、引用、说话） | `SKILL.md`（四作用域） | 长，按需读 | 人（复核后修订） |
**记忆层** | 这个人的偏好、纠正过的事 | `homes/<uid>/memories/`（引擎 phase1/2 整理） | 跨项目跟随人 | 引擎 |
**引用层** | 谁引用了什么、被确认过几次 | `citation` 账本（待建） | 几年 | 服务记账 |

四层各自有**唯一写者**，不互相覆盖 —— 这是能长期跑下去的前提。

---

## 三、自动化分级（每一级都要真实信号，不靠我们自己打分）

```
L1 记账       被引用一次 → used_count +1                     （已有：cites 已落库）
L2 核验       复核判「依据成立」 / 人签发 → verified_count +1   （下一步）
L3 权威       一致性达标（同 ref 同 quote，verified≥5、used≥10）
              → 导出 kb/authoritative/<slug>.md（带出处与确认次数）
L4 流程修订   复核反复指出同一类问题 → 生成一条"疑似缺流程"的观察，
              进人工队列；人改了 SKILL.md 才算数（不自动改）
```

**为什么 L4 不自动**：技能是行为规则，自动改会把一次偶然变成永久偏差。
但**观察是自动的**：同类问题出现 3 次，就把"证据"摆到人面前。

---

## 四、这四层怎么让它"更聪明"（具体机制，不是口号）

| 现象 | 机制 | 不这么做会怎样 |
|---|---|---|
同一句话问法不同，回答不一致 | 事实层是文件，走同一条检索（grep + locator） | 每次凭记忆答，答案飘 |
依据时有时无 | 引用层记账 + 核验，权威条目优先被检索到 | 模型每次重新判断"该不该引用" |
同类错误反复犯 | L4 观察 → 人改技能 | 靠提示词补一句，越补越乱 |
换个项目就忘 | 项目知识在项目工作区，个人记忆在家目录 | 两处混存，越用越脏 |

## 五、四条"不许硬编码"的判据（写进 loop prompt）

```
1. 这句话会不会因为加工具/换模型而失效？会 → 不许写进 AGENTS.md
2. 这个判断能不能交给模型（有工具可依）？能 → 后端不许写 if
3. 这个限制是不是在替模型删内容/改结论？是 → 删掉（今天刚删了 160 字截断）
4. 这份数据有没有唯一写者？没有 → 先想清楚再动
```

## 六、度量（看得出来是不是真的在变聪明）

```
引用命中率     回答里有出处的比例（目标：业务类回答 > 60%）
复核一次通过率 复核不需要"必须改"的比例（目标：逐月上升）
权威条目数     authoritative 条目增长（目标：稳定增长，不是暴涨）
重复错误率     同类"必须改"在 8 周内是否复发（目标：下降）
```

**这四个数都是可查的**：都在 `citation` 账本、`audit_log`、复核结果里。

---

## 七、明确不做

```
✗ 靠堆提示词让它"更聪明"
✗ 给权威度写死权重（次数必须来自真实确认）
✗ 自动改技能（会放大偶然）
✗ 只优化最近几轮（那不是学习，是缓存）
✗ 把聊天记录当知识（会话可丢，知识要留）
```

---

## 八、现状与下一步

```
已有：事实层（kb 186 文件 + records + standards）、程序层（5 个技能）、
      记忆层（引擎整理）、引用（cites 已落库，含 std/quote）
缺：  L2 核验（复核/签发 → verified）、L3 权威导出、L4 观察队列
```

顺序：L2 → L3 → L4。L2 一做完，L3 就是一次查询；L4 只在有 20+ 份真实文书后再开。
