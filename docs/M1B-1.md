# M1b-1 · legacy `memory` → v2 `memory_item` 映射与回填

> 关联：`docs/MEMORY-V2.md` §3/§9、`docs/M1-DESIGN.md`。
> 范围：**schema 扩展（0002）+ 幂等回填工具 + 只读验收**；在 `jl_m2`（生产 jl 的克隆）验证。
> 本轮**不对生产 jl 执行 0002/回填**，不改 legacy `memory` 表，不加运行时双写。

## 1. 0002 迁移

`db/migrations/0002_memory_v2_legacy_map.sql`：

```sql
ALTER TABLE memory_item
  ADD COLUMN legacy_memory_id BIGINT UNSIGNED NULL
    COMMENT '来源 legacy memory.id；NULL=非导入行（幂等回填唯一键）',
  ADD UNIQUE KEY uk_legacy_memory (legacy_memory_id);
```

- 只改 `memory_item`；`UNIQUE KEY` 保证同一 legacy id 只回填一次。
- down：`ALTER TABLE memory_item DROP INDEX uk_legacy_memory, DROP COLUMN legacy_memory_id;`
- 不改 legacy `memory` 表、不改 0001、不新增其它表。

## 2. 字段映射

| legacy `memory` | v2 `memory_item` | 规则 |
|---|---|---|
| `id` | `legacy_memory_id` | 唯一映射键（幂等） |
| `text` | `canonical_text` | 原样复制 |
| `source_ref` | `evidence` | 原样复制（可为 NULL；当前 39 行全 NULL） |
| — | `kind` | 固定 `'rule'` |
| — | `status` | 固定 `'candidate'`（自动导入永不直接 active） |
| — | `created_by` | 固定 `'import'` |
| — | `confidence` | 固定 `0.500` |
| — | `expires_at` | 回填时刻 `NOW() + 14 天`（candidate 过期口径） |
| `scope='project'` | `scope='project'` | `scope_id=owner_id`，`project_id=owner_id` |
| `scope='user'` + `project_id` 非空 | `scope='project_user'` | `scope_id=owner_id`(user_id)，`project_id=project_id` |
| `scope='user'` + `project_id` 空 | `scope='user'` | `scope_id=owner_id`(user_id)，`project_id=NULL` |

当前生产数据（39 行）分布：`project=24`（owner_id=项目 id）、`user=15`（owner_id=user_id，
`project_id` 全 NULL），因此预期映射为 `project=24 / user=15 / project_user=0`。
`status`（legacy tinyint 1/0）本轮不参与映射，39 行全部进 `candidate`。

## 3. 回填工具 `scripts/backfill-memory-v2.py`

- `--database`（默认 `jl_m2`）；**默认拒绝 `jl`**：生产必须 `--allow-production` +
  进程环境 `JL_ALLOW_PROD_MIGRATION=1`（`--execute` 另需有效 gzip `--backup`）。
- `--dry-run`（默认）：只打印 legacy 行数、已映射数、将插入数、按 scope 计数、映射规则；
  **不写库**。
- `--execute`：单条 `INSERT ... SELECT`，LEFT JOIN `legacy_memory_id` 过滤已映射行；
  事务内执行，前后对比 legacy 全表指纹（行数 + 内容 sha256），不一致立即回滚。
  输出 `BACKFILL_OK (inserted=..., re-run would insert 0)`。
- 幂等：`uk_legacy_memory` + LEFT JOIN；重复 `--execute` 插入 0 行。
- **只读 legacy `memory`**：全脚本只有 `SELECT` 读它；不 UPDATE / DELETE / 改结构。

## 4. 只读验收 `scripts/check-m1b-mapping.py`

默认库 `jl_m2`，只读（`SET SESSION transaction_read_only=1`）：

1. `memory_item.legacy_memory_id` 列存在、`BIGINT UNSIGNED NULL`、有单列 UNIQUE 索引；
2. `schema_migrations` 有 0002 记录且 checksum 与仓库文件一致；
3. legacy `memory` 表仍在、原列未变、行数 = 39（`--expect-legacy-rows` 可调）；
4. 每条 legacy 行都已映射（无遗漏/无孤儿/无重复），所有 v2 行都来自 legacy；
5. scope 计数与映射规则一致；逐条字段（kind/status/created_by/confidence/
   canonical_text/evidence/scope/scope_id/project_id）正确；`expires_at` 在
   `[now, now+15 天]`；
6. 幂等证据：再跑回填将插入 0 行。通过打印 `M1B_MAPPING_OK`。

## 5. jl_m2 测试步骤（不碰生产 jl）

```bash
# 0) 克隆生产 jl（只读 dump）到 jl_m2
docker exec jl-mysql mysql -uroot -p"$ROOTPW" -e "CREATE DATABASE IF NOT EXISTS jl_m2 CHARACTER SET utf8mb4; GRANT ALL PRIVILEGES ON \`jl_m2\`.* TO 'jl'@'%'; FLUSH PRIVILEGES;"
docker exec jl-mysql mysqldump -uroot -p"$ROOTPW" --default-character-set=utf8mb4 --single-transaction --routines jl | docker exec -i jl-mysql mysql -uroot -p"$ROOTPW" jl_m2

# 1) 克隆已含 0001（schema_migrations 有 0001），只需应用 0002
python3 scripts/migrate.py --env-file /path/.env --database jl_m2          # APPLY 0002
python3 scripts/migrate.py --env-file /path/.env --database jl_m2 --check  # MIGRATIONS_OK

# 2) 回填 dry-run -> execute -> 幂等
python3 scripts/backfill-memory-v2.py --env-file /path/.env --database jl_m2 --dry-run
python3 scripts/backfill-memory-v2.py --env-file /path/.env --database jl_m2 --execute
python3 scripts/backfill-memory-v2.py --env-file /path/.env --database jl_m2 --execute   # inserted=0

# 3) 验收
python3 scripts/check-m1b-mapping.py --env-file /path/.env --database jl_m2   # M1B_MAPPING_OK

# 4) 0002 回滚/重放（migrate.py 按倒序回滚已应用迁移：0002 -> 0001）
python3 scripts/migrate.py --env-file /path/.env --database jl_m2 --rollback
#   -> 0002 down 去列/键；0001 down 删 5 表；legacy memory 不动
python3 scripts/migrate.py --env-file /path/.env --database jl_m2          # 重新应用 0001+0002
python3 scripts/backfill-memory-v2.py --env-file /path/.env --database jl_m2 --execute
python3 scripts/check-m1b-mapping.py --env-file /path/.env --database jl_m2
```

## 6. 生产现状与边界

- 生产 `jl` 已应用 **0001**（25 张表）；`memory_item` 5 张 v2 表 0 行；legacy `memory` 39 行。
- 本轮**不**对 `jl` 应用 0002、不回填；`jl.memory_item` 暂无 `legacy_memory_id` 列。
- 回填只写 `jl_m2`；v2 与 legacy 并存，0002 可 down 回滚（只去映射列）。
- 明确不做：BFF 读路径切换、双写、legacy 表清理（M2+ / M1b-2）。
