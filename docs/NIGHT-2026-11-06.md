## 二、今天修掉的真问题（都带证据）

**用户可见的（最要紧）**

1. **手机补的字段被静默丢掉**，还标成「待签」
   → 监理员以为填好了，签发时才发现是空的。
2. **缺字段的文书能被标成「已签」** → 加了拦截。
3. **不能只改状态** → 签发要重发全部字段，改成只传 state 即可。
4. **`artifact` 永远为空** → 客户端拿不到「这一单的文书」。
5. **同一个按钮点了没反应**（5 处原型占位）→ 相机、资料、导出全部接真或改诚实文案。

**会咬人的（不报错、不崩、界面说成功）**

6. **串单**：出稿结果写在项目级共享的 `.agent/last.md`，两人同项目同时用会互相覆盖。
7. **语音转写串号**：`/tmp/jl-asr.wav` 全局共用。
8. **复核互踩**：`/tmp/jl-review` 全局共用。
9. **自愈是假的**：healthcheck 用旧入口 `server.py` 重启且不带环境变量
   → 挂了以后「重启成功」，实际跑旧代码、退化成 CLI、没有复核。
10. **备份漏了一半**：只备 db + workspaces，**照片和记忆从来没备过**。
11. **权限**：`data/homes`（记忆）和 `data/blobs`（现场照片）对同机其他用户可读。
12. **六处静默失败**：含学习功能、复核缺项、线程历史 —— 全是 `except: pass` 吞掉。

## 三、我自己犯的错（也记下来）

```
1. progress.sh 里查「待补」没带 utf8mb4 → 报了几个月 0（实际 132）
2. 前端 _reviewOf 只写调用没写定义 → 任务完成即 TypeError
3. core.py 四处调用没导入 → 被 except 吞掉
4. audit-auth 第一版假阴性（说"全部有校验"，实际 13 个没校验）
5. 验证日志轮转时原地 truncate 生产日志，搞成 61MB 垃圾
6. 六次「查错东西」：用 POST 打 GET 路由、查 audit（真名 audit_log）、
   把 data 当字典、拿不存在的列查 task、用 800 字节判中文文档……
```

**结论：我最大的风险不是不会写，是"太快下结论"。** 所以做了三样东西管住自己：

```
preflight   抓「调用了不存在的东西」「静默失败」「硬编码」
whatison    一条命令列出真实路由/表列/路径（别猜）
smoke-e2e   13 项端到端断言（今天抓出 artifact 永远为空）
```

```
每天 04:00  cleanup_temp    清临时产物 + 日志轮转
每天 09:00  devloop         preflight + 结构快照 + 数据不变量（只读）
每周日 09:30 smoke-e2e      端到端 13 项（自清理）
每天 18:00  pending_docs    统计待补并留痕
开机        docker up + start-bff + healthcheck
```

**分界按你说的**：服务要的和开发要的都放服务器 —— 事实在服务器上。
